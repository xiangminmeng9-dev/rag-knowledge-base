# 功能规范: RAG 智能知识库问答系统

**功能分支**: `001-rag-knowledge-base`
**创建时间**: 2026-03-30
**状态**: 草稿
**输入**: 用户描述: "开发一个 RAG 系统，前台页面支持用户选中知识库进行智能问答，后台可以新建知识库后上传文档，并支持多种格式文件上传。支持多种切分策略和 embedding 模型选择，查询改写，后台仪表盘统计。"

## 用户场景与测试 *(必填)*

### 用户故事 1 - 用户登录与知识库问答 (优先级: P1)

作为一名普通用户，我希望登录系统后选择一个知识库，然后输入问题获得基于该知识库内容的智能回答，以便快速获取所需信息而无需手动翻阅文档。

**优先级原因**: 这是系统的核心价值——用户能够通过自然语言向知识库提问并获得准确回答。没有此功能，系统不具备任何使用价值。

**独立测试**: 可以通过预置一个包含已上传文档的知识库，用户登录后选择该知识库并提问来完全测试。交付价值：用户能基于知识库内容获得智能回答。

**验收场景**:

1. **给定** 用户尚未登录, **当** 用户访问系统首页时, **那么** 系统显示登录页面，要求输入用户名和密码
2. **给定** 用户已登录且存在多个知识库, **当** 用户进入问答页面时, **那么** 系统显示该用户有权限访问的知识库列表供选择
3. **给定** 用户已选择一个知识库, **当** 用户输入问题并提交时, **那么** 系统基于该知识库的内容返回相关回答，并展示引用的来源文档片段
4. **给定** 用户正在进行问答, **当** 用户提交一个与知识库内容无关的问题时, **那么** 系统告知用户该问题超出当前知识库范围
5. **给定** 用户正在问答, **当** 用户切换到另一个知识库时, **那么** 问答上下文重置，后续回答基于新选择的知识库内容

---

### 用户故事 2 - 超级管理员用户管理与权限配置 (优先级: P1)

作为超级管理员，我希望登录后台管理页面后能够创建新用户并为其分配不同的权限角色，以便控制不同用户对系统功能的访问范围。

**优先级原因**: 权限管理是多用户系统的基础设施。不同用户需要不同的访问级别——普通用户只能问答，知识库管理员可以构建知识库。此功能是其他管理功能的前提。

**独立测试**: 可以通过超级管理员登录后台，创建两个不同权限的用户，然后分别用这两个用户登录验证权限隔离来测试。交付价值：系统具备多用户和权限控制能力。

**验收场景**:

1. **给定** 超级管理员已登录后台, **当** 管理员点击"创建用户"时, **那么** 系统显示用户创建表单，包含用户名、密码、权限角色等字段
2. **给定** 超级管理员正在创建用户, **当** 管理员选择"问答用户"角色时, **那么** 该用户登录后只能访问前台问答页面，无法访问后台管理功能
3. **给定** 超级管理员正在创建用户, **当** 管理员选择"知识库管理员"角色时, **那么** 该用户登录后可以访问后台的知识库管理功能（创建知识库、上传文档等）
4. **给定** 超级管理员已登录后台, **当** 管理员查看用户列表时, **那么** 系统显示所有已创建用户及其角色信息，支持编辑和禁用操作

---

### 用户故事 3 - 知识库创建与文档上传 (优先级: P1)

作为知识库管理员，我希望在后台创建新知识库并上传多种格式的文档，以便将组织内的知识内容数字化并供用户查询。

**优先级原因**: 知识库的创建和文档上传是 RAG 系统内容侧的核心流程。没有内容，问答功能无法运作。

**独立测试**: 可以通过管理员登录后台，创建一个新知识库，上传不同格式的文档（PDF、Word、TXT、Markdown），确认文档成功处理并可用于问答来测试。交付价值：系统可以接收和存储知识内容。

**验收场景**:

1. **给定** 管理员已登录后台, **当** 管理员点击"新建知识库"时, **那么** 系统显示创建表单，包含知识库名称和描述字段
2. **给定** 一个已创建的知识库, **当** 管理员进入该知识库详情页时, **那么** 系统显示文档上传区域和已上传文档列表
3. **给定** 管理员正在上传文档, **当** 管理员选择 PDF、Word (.docx)、TXT 或 Markdown 文件时, **那么** 系统接受上传并显示处理进度
4. **给定** 管理员尝试上传文档, **当** 文件格式不受支持时, **那么** 系统提示不支持该格式并列出支持的格式列表
5. **给定** 管理员已上传文档, **当** 管理员查看文档列表时, **那么** 每个文档显示文件名、格式、大小、上传时间和处理状态

---

### 用户故事 4 - 文档切分策略配置 (优先级: P2)

作为知识库管理员，我希望在上传文档时选择不同的文本切分策略并设置重叠比例，以便根据文档内容特点优化检索效果。

**优先级原因**: 切分策略直接影响 RAG 检索质量。不同类型的文档适合不同的切分方式，灵活的策略配置能显著提升问答准确性。

**独立测试**: 可以通过上传同一文档分别使用不同切分策略，对比生成的文档块数量和内容来测试。交付价值：管理员可以针对不同文档类型优化检索效果。

**验收场景**:

1. **给定** 管理员正在上传文档, **当** 系统显示切分配置选项时, **那么** 可选策略包括：语义切分、递归切分、段落切分、固定大小切分、特殊字符切分
2. **给定** 管理员已选择切分策略, **当** 管理员设置重叠比例时, **那么** 系统接受 0% 到 50% 之间的百分比值
3. **给定** 管理员选择"固定大小切分", **当** 管理员配置参数时, **那么** 系统允许设置每块的字符数（默认值 500 字符）
4. **给定** 管理员未主动选择策略, **当** 管理员直接上传文档时, **那么** 系统使用默认策略（递归切分，重叠比例 10%）

---

### 用户故事 5 - Embedding 模型选择与向量存储 (优先级: P2)

作为知识库管理员，我希望为知识库选择不同的 embedding 模型，以便根据使用场景和语言特点选择最合适的向量化方案。

**优先级原因**: 不同 embedding 模型在不同语言和领域的表现差异明显，灵活选择能提升检索准确率。此功能依赖于知识库和文档上传的基础能力。

**独立测试**: 可以通过创建知识库时选择不同 embedding 模型，上传相同文档后对比问答效果来测试。交付价值：管理员可根据内容特点选择最优的向量化方案。

**验收场景**:

1. **给定** 管理员正在创建或编辑知识库, **当** 系统显示 embedding 配置时, **那么** 显示可用的 embedding 模型列表（至少包含 2 种可选模型）
2. **给定** 管理员已选择 embedding 模型, **当** 文档上传并处理完成时, **那么** 文档向量化数据存入 Chroma 数据库，并在该知识库的命名空间下隔离存储
3. **给定** 一个已有文档的知识库, **当** 管理员切换 embedding 模型时, **那么** 系统提示需要重新处理已有文档，并询问是否确认

---

### 用户故事 6 - 后台仪表盘与统计概览 (优先级: P2)

作为后台管理员，我希望在管理首页看到系统关键数据的统计概览，以便快速了解系统使用情况和内容规模。

**优先级原因**: 统计概览为管理员提供系统运行状态的全局视角，有助于容量规划和管理决策。

**独立测试**: 可以通过创建若干知识库并上传文档后，登录后台验证统计数据是否准确来测试。交付价值：管理员一目了然地掌握系统整体状况。

**验收场景**:

1. **给定** 管理员已登录后台, **当** 管理员进入仪表盘页面时, **那么** 系统显示：知识库总数、文档总数、用户总数等核心统计指标
2. **给定** 系统中已有数据, **当** 管理员查看仪表盘时, **那么** 统计数据以图表形式可视化展示（如柱状图、饼图、折线图等）
3. **给定** 管理员新增了一个知识库并上传了文档, **当** 管理员刷新仪表盘时, **那么** 统计数据实时更新反映最新状态

---

### 用户故事 7 - 查询改写 (优先级: P3)

作为用户，我希望系统能够自动优化我输入的查询内容，以便在我的问题表述不够精确时也能获得高质量的回答。

**优先级原因**: 查询改写提升了检索召回率和回答质量，是 RAG 系统体验优化的重要环节。但系统在没有查询改写的情况下仍可正常运行，属于增强型功能。

**独立测试**: 可以通过输入一个模糊或口语化的查询，对比系统改写前后的检索结果质量来测试。交付价值：用户无需精心组织问题措辞也能获得准确回答。

**验收场景**:

1. **给定** 用户正在问答, **当** 用户输入一个模糊或口语化的问题时, **那么** 系统在检索前自动改写查询以提升检索精度
2. **给定** 系统已改写查询, **当** 回答展示时, **那么** 用户可以看到原始查询和改写后的查询内容（可折叠展示）
3. **给定** 用户不希望系统改写, **当** 用户关闭查询改写功能时, **那么** 系统直接使用原始输入进行检索

---

### 边界情况

- 当用户上传空文件或内容极少的文档时会发生什么？系统应提示文件内容不足，无法有效切分
- 当上传的文档大小超出限制（默认 50MB）时会发生什么？系统应拒绝上传并提示大小限制
- 当 Chroma 数据库连接失败时会发生什么？系统应显示友好错误信息并允许重试
- 当 embedding 模型服务不可用时会发生什么？系统应提示服务暂不可用，已上传文档标记为"待处理"
- 当用户同时上传多个文档时会发生什么？系统应支持批量上传，逐个处理并显示各自进度
- 当超级管理员被禁用或删除时会发生什么？系统应禁止删除最后一个超级管理员账户
- 当知识库内没有任何文档时，用户尝试问答会发生什么？系统应提示该知识库暂无可用内容

## 需求 *(必填)*

### 功能需求

**认证与权限**
- **FR-001**: 系统必须支持用户通过用户名和密码登录
- **FR-002**: 系统必须支持三种用户角色：超级管理员、知识库管理员、问答用户
- **FR-003**: 超级管理员必须能够创建、编辑、禁用用户并分配角色
- **FR-004**: 问答用户登录后只能访问前台问答页面
- **FR-005**: 知识库管理员登录后可以访问后台的知识库管理功能
- **FR-006**: 超级管理员拥有所有权限，包括用户管理和知识库管理
- **FR-006a**: 管理员必须能够为每个用户分配可访问的知识库列表，用户仅能看到和使用被授权的知识库

**知识库管理**
- **FR-007**: 管理员必须能够创建知识库，包含名称和描述信息
- **FR-008**: 管理员必须能够查看、编辑和删除知识库
- **FR-009**: 每个知识库的向量数据必须在存储中隔离

**文档上传与处理**
- **FR-010**: 系统必须支持上传 PDF、Word (.docx)、TXT、Markdown 格式的文档
- **FR-011**: 系统必须支持以下文本切分策略：语义切分、递归切分、段落切分、固定大小切分、特殊字符切分
- **FR-012**: 系统必须支持设置切分重叠比例（0%~50%）
- **FR-013**: 系统必须在文档上传后自动执行文档解析、切分、向量化和存储流程
- **FR-014**: 系统必须显示每个文档的处理状态（上传中、处理中、已完成、失败）

**Embedding 与向量存储**
- **FR-015**: 系统必须支持选择不同的 embedding 模型（至少 2 种可选）
- **FR-016**: 向量化数据必须存入 Chroma 数据库
- **FR-017**: 切换知识库的 embedding 模型时，系统必须提示需重新处理已有文档

**智能问答**
- **FR-018**: 用户必须能够选择知识库后输入自然语言问题进行问答
- **FR-018a**: 系统必须支持多轮对话，在同一会话中保持问答上下文，用户可以基于前一轮回答进行追问
- **FR-018b**: 系统必须支持多个 LLM 提供商（如 OpenAI、Claude、通义千问等），管理员可在后台配置和切换当前使用的 LLM 服务
- **FR-019**: 系统回答必须包含引用来源（来源文档片段）
- **FR-020**: 系统必须支持查询改写功能，可由用户开关控制
- **FR-021**: 启用查询改写时，用户可以查看原始查询和改写后的查询内容

**仪表盘**
- **FR-022**: 后台仪表盘必须显示知识库总数、文档总数、用户总数等核心统计指标
- **FR-023**: 统计数据必须以图表形式可视化展示

### 关键实体

- **用户 (User)**: 系统的使用者，关键属性包括用户名、密码（加密存储）、角色、创建时间、状态（启用/禁用）。一个用户通过管理员分配获得对特定知识库的访问权限。
- **角色 (Role)**: 用户的权限级别，包含超级管理员、知识库管理员、问答用户三种。决定用户可以访问的功能范围。
- **用户-知识库授权 (UserKnowledgeBaseAccess)**: 用户与知识库之间的多对多访问关系，由管理员分配。用户仅能看到和使用被授权的知识库。
- **知识库 (KnowledgeBase)**: 知识内容的逻辑容器，关键属性包括名称、描述、关联的 embedding 模型、创建时间。一个知识库包含多个文档。
- **文档 (Document)**: 上传到知识库的文件，关键属性包括文件名、格式、大小、上传时间、处理状态、切分策略、重叠比例。属于某个知识库。
- **文档块 (Chunk)**: 文档切分后的文本片段，关键属性包括文本内容、向量表示、来源文档、在文档中的位置。用于检索和回答生成。
- **对话 (Conversation)**: 用户与知识库之间的问答会话，支持多轮对话并保持上下文记忆。包含多条按时序排列的问答记录。关联用户和知识库。用户可追问，系统基于历史上下文理解后续问题。

### 假设

- 系统初始部署时预置一个超级管理员账户
- 系统预期服务规模：个人/小团队使用（少于 50 个用户，少于 10 个知识库）
- 文档大小上限默认 50MB，可通过配置调整
- 默认切分策略为递归切分，重叠比例 10%
- 查询改写功能默认开启
- embedding 模型列表可通过配置扩展
- 用户登录采用基于会话的认证方式（JWT token）
- 结构化业务数据（用户、知识库元数据、对话记录等）使用 SQLite 文件数据库存储，通过 ORM 访问
- LLM 提供商配置包含 API 地址、API Key、模型名称等参数，管理员通过后台系统设置页面管理

## 成功标准 *(必填)*

### 可衡量的结果

- **SC-001**: 用户从登录到完成首次问答的操作步骤不超过 4 步（登录 → 选择知识库 → 输入问题 → 获得回答）
- **SC-002**: 系统对用户问题的回答在 10 秒内返回（含检索和生成）
- **SC-003**: 90% 的用户在首次使用时能独立完成问答流程，无需额外指导
- **SC-004**: 管理员从创建知识库到完成首次文档上传的操作步骤不超过 5 步
- **SC-005**: 系统支持同时处理至少 5 个文档上传任务
- **SC-006**: 仪表盘统计数据在数据变更后 30 秒内更新
- **SC-007**: 启用查询改写后，对模糊查询的回答相关性显著高于未改写时
- **SC-008**: 所有支持的文档格式上传成功率达到 99% 以上
